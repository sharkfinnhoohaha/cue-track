The plan to make the detector reliably find the intro, verses, choruses, bridge and outro. The grader is built so the loop can’t fake the number: 90% here means genuinely 90% on songs it never tuned on.

The rule that keeps it honest

Plausibility ≠ accuracy, and you never tune on the test set

  • Sanity checks (“does this look like a real song?”) catch obvious errors — 7 verses, a dozen choruses — instantly, with no labels. They trigger a retry. They are never part of the score, or the model could win by always printing a textbook structure.
  • Accuracy is only ever measured against ground-truth labels, on a locked test split the loop can’t touch (a per-song hash + an evaluation budget enforce it).
  • So a reported 90% is real — not a model that learned to please the grader.

Do it — step by step

1

Deploy the allin1 worker you, once

It’s the teacher (auto-labels) and possibly the answer (if it’s already ≥90%, route to it). One build (~30 min the first time). Full notes in services/ml-worker/DEPLOY.md.

openssl rand -hex 32 > ~/.cuetrack-ml-worker-secret && chmod 600 ~/.cuetrack-ml-worker-secret

gcloud run deploy cuetrack-ml-worker \
  --source services/ml-worker --region us-east1 --project overlook-works \
  --port 8080 --memory 4Gi --cpu 2 --timeout 300s \
  --min-instances 0 --max-instances 5 --no-cpu-throttling --allow-unauthenticated \
  --set-env-vars="WORKER_SHARED_SECRET=$(cat ~/.cuetrack-ml-worker-secret)"

Then set ML_WORKER_URL + ML_WORKER_SHARED_SECRET in your shell (and Vercel), keep ANALYZE_AB_SPLIT_PERCENT=0 until measured.

2

Drop in audio & auto-label it agent

Put the songs in corpus/audio/. The teacher labels them all and flags any that look implausible (so you trust it before relying on it).

npm install
ML_WORKER_URL=… ML_WORKER_SHARED_SECRET=… \
  npx tsx eval/sections/label-with-teacher.ts --audio corpus/audio --out corpus
3

Make the test set trustworthy you, ~15 min

Correct ~8 of the test-split songs’ labels by hand (allin1’s silver → gold) so the held-out number is real. The agent tells you which songs are in test; you fix those label files.

4

Measure allin1 — you might be done agent

If allin1 already clears 90%, the fastest win is to route users to it — no detector surgery needed.

npx tsx eval/sections/run-eval.ts --corpus corpus --split test --allow-test \
  --via http --detector ml

≥90% & clean guards → set ANALYZE_AB_SPLIT_PERCENT=100 and stop. Otherwise → the loop.

5

Run the improvement loop agent

Baseline Foote, then iterate: read the worst songs & the “7 verses” flags, make one general fix (the repetition-based chorus labeler is the big one), keep it only if dev improves and the sealed test holds. Grade a batch every ~10 iterations.

# baseline + instant structural flags
npx tsx eval/sections/run-eval.ts --corpus corpus --split dev

# test a constraint's effect on accuracy (A/B)
npx tsx eval/sections/run-eval.ts --corpus corpus --split dev --postprocess

# unattended parameter search for a few hours
npx tsx eval/sections/tune.ts --corpus corpus --minutes 180 --target 0.9
6

Confirm on the held-out set & ship agent

Only a green test run counts. Open a PR with the winning Foote config; you flip it on the worker.

npx tsx eval/sections/run-eval.ts --corpus corpus --split test --allow-test
# meetsTarget: true  →  done

Hand it to the agent

Point it at the repo with the audio present and give it:

Read eval/sections/HANDOFF.md and execute it. Drive section detection to
